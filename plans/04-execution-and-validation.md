# 04 — Execution, interruption, and validation

Status: proposed design, 2026-11-15. This is an implementation plan, not a claim that the harness exists. It covers the execution and evidence plane for a Rust-based streaming coding harness around T3 Code, with Inspector/Live Gallery-style views. It does not propose replacing T3's orchestrator or reproducing Inspector's proprietary implementation.

## 1. Evidence and integration boundary

The evidence below is source inspection, not a live test of a particular installed T3 version. Pin and capability-probe the deployed version before implementation; upstream `main` can change. The inspected upstream snapshot is [`86dbf2abd18e631da1061f3a2489da603b2cc242`](https://github.com/pingdotgg/t3code/tree/86dbf2abd18e631da1061f3a2489da603b2cc242), resolved from `main` on 2026-11-15.

- T3's [V2 architecture document](https://github.com/pingdotgg/t3code/blob/86dbf2abd18e631da1061f3a2489da603b2cc242/docs/orchestration-v2/README.md) describes app-owned IDs, runs and nested execution nodes, normalized durable events, existing snapshot/cursor projection infrastructure, and command receipts. It explicitly labels parts as a target architecture; do not infer a deployed feature from the document alone. Its Codex probes say interrupt request acknowledgement precedes the authoritative turn completion and a child turn may finish before its parent.
- The [MCP contract](https://github.com/pingdotgg/t3code/blob/86dbf2abd18e631da1061f3a2489da603b2cc242/docs/orchestration-v2/orchestrator-mcp-server.md) documents `t3_thread_read` as a bounded, paginated durable **timeline** read, `t3_thread_wait`, and `t3_thread_interrupt` for a selected run. Timeline reads are not demonstrated here to be a lossless token/delta stream; do not call them one. The documented provider-session MCP credential is scoped and expires. External clients need a supported authentication/transport contract, not a copied provider token.
- In the pinned [ThreadManagementService](https://github.com/pingdotgg/t3code/blob/86dbf2abd18e631da1061f3a2489da603b2cc242/apps/server/src/orchestration-v2/ThreadManagementService.ts), normal interruption dispatches `run.interrupt`; `forceStopThread` checks the target under a thread lock, kills an agent scope only if it is owned by the thread, settles applicable background work, and guards newer runs during session cleanup. The service interface alone does **not** establish that an external MCP client can invoke force stop; discover and test the actual exposed transport and authorization. Do not reach into an internal service or kill a shared provider process as a fallback.
- The pinned [Codex adapter](https://github.com/pingdotgg/t3code/blob/86dbf2abd18e631da1061f3a2489da603b2cc242/apps/server/src/orchestration-v2/Adapters/CodexAdapterV2.ts) processes command-output deltas for settled turns and synthesizes terminal command items on certain interrupted/failed turns. A terminal display item is not independent proof that an OS process has exited. Provider-specific ability to stop an individual command is not established by this inspection.
- In this checkout, `src/events.rs`, `src/app.rs`, and `src/server.rs` implement file add/update/remove/reset over an in-memory broadcast (capacity 4096); a lagged subscriber gets `reset`. This is useful for gallery refresh, not durable agent-event replay, process control, or exactly-once delivery. `README.md` describes the Rust gallery's Axum/Tokio server and watched files; the Python implementation remains its stated reference. The local `inspector-feature-inventory/INSPECTOR-FEATURE-INVENTORY.md` reports observed feed, selection, history, compare and pause behavior with explicit testing caveats. Treat these as interaction references, not an Inspector API or a persistence guarantee.

**Recommended initial boundary:** T3 remains authoritative for its threads, provider turns, approvals, and provider-owned commands. A separate Rust service subscribes through a documented, versioned T3 projection stream if one is externally supported; otherwise it uses incremental MCP timeline reads and labels its coverage `timeline-only`. The Rust service owns only its own ingestion journal, projections, UI delivery, and commands it explicitly spawns. Negotiate capabilities at connection; show unavailable actions as unavailable. A purpose-built T3 adapter/extension is required before claiming real-time lossless provider deltas or remote per-command termination. Do not parse T3 SQLite files, diagnostic logs, PTY screen output, or internal endpoints as a stable contract.

## 2. Contracts and data model

### Identifiers and envelopes

Use typed, opaque IDs: `environment_id`, `thread_id`, `run_id`, `attempt_id`, `node_id`, `command_id`, `request_id`, `event_id`, `source_epoch`, and `artifact_id`. `attempt_id` distinguishes retry/restart executions; `node_id` identifies a command or nested operation, not a PID. T3 IDs are stored as external references with their environment; harness IDs are separate. An optional source correlation ID and source cursor are useful only under their source's documented rules.

An illustrative JSON envelope, with explicit evolution rules:

```json
{
  "schema": "harness.event/1", "event_id": "01...", "seq": 842,
  "source": {"kind": "t3", "epoch": "connection-generation", "cursor": "opaque"},
  "scope": {"environment_id": "env", "thread_id": "thr", "run_id": "run", "attempt_id": "att", "node_id": "node"},
  "kind": "command.output", "observed_at": "2026-11-15T00:00:00Z",
  "source_time": null, "causation_id": null, "payload": {"stream": "stdout", "offset": 4096, "text": "..."}
}
```

`seq` is a monotonically increasing **local commit order**, scoped to one database, never an asserted global causal order; wall clocks are display metadata. Nullable fields stay null when unknown. On schema upgrades, additive fields and unknown event kinds are preserved and surfaced as unsupported; incompatible major versions require a negotiated migration. Normalize source data without inventing provider state. Deduplicate by a documented stable source event ID/cursor; absent one, retain the event and use an idempotent state projection where possible. Do not deduplicate arbitrary identical text chunks.

Minimum normalized kinds and payloads:

| Kind | Essential payload / semantics |
| --- | --- |
| `run.created`, `run.state` | state and source version; active, stopping, completed, failed, interrupted, cancelled, unknown; `run.state` terminal applies to root only |
| `node.created`, `node.state` | parent, kind, state, source ID; child completion does not close root |
| `message.delta`, `message.final` | item ID, stream revision or offset when available; final replaces/commits accumulated text |
| `command.started`, `command.output`, `command.exit` | owner (`harness`, `t3`, `unknown`), stream offsets if provided, background flag, exit code/signal and provenance; exit can follow run terminal |
| `approval.requested`, `approval.resolved` | opaque request ID, scope, deadline if any; response capability and state, not secrets |
| `interrupt.requested`, `interrupt.acknowledged`, `interrupt.result` | target, mode, request ID, actor, outcome, and whether source-confirmed, locally observed, or unknown |
| `artifact.observed`, `artifact.removed` | watched root ID + relative path, file version metadata, observation time, optional verified producing node; source `filesystem` |
| `stream.gap`, `source.health` | source/epoch, missing or unknown range, reason, retry state; explicitly mark irrecoverable loss |

A filesystem notification proves only that a file was observed. Correlate it to a run only with explicit producer metadata or a documented capture mechanism; otherwise show “unattributed,” even if timestamps match. An artifact can be updated again after run completion. History is versioned only if bytes were actually retained: metadata changes alone are not recoverable revisions.

### Persistence and replay

Start with SQLite in WAL mode, a single serialized writer, migrations, foreign keys, and transactionally committed `events(seq, event_id, source, source_key?, kind, payload, ...)`, current `runs/nodes/commands/artifacts` projections, `source_checkpoints`, `requests` (idempotency receipt + target), and an `effects` outbox. Store full text or output in bounded chunks with offsets; store immutable artifact blobs separately by content hash only when capture is explicitly enabled. Define retention per category with size and age limits. Never evict active unprocessed effects or an event required for the published snapshot. Encrypt sensitive data at rest if the deployment requires it; file permissions alone do not encrypt.

One transaction appends the event, updates projections, records any new outbox effect, and advances the **source** cursor only if the source guarantees it is safe to checkpoint that item. Commit before fan-out. A unique source key can suppress replay only if source guarantees uniqueness and stable reuse. Journal writes failing or quota exhaustion stop accepting new mutating requests and mark ingestion degraded; do not acknowledge data as durable when it is not.

Expose `GET /v1/snapshot` returning a transactionally consistent projection and high-water local `seq`, then `GET /v1/events?after=<seq>` using SSE (or authenticated WebSocket) for durable catch-up followed by live delivery. Read journal `seq > cursor` until caught up, register/wake and re-query by `seq`; the journal, not a notification queue, is authoritative, so the snapshot/subscribe boundary cannot lose an event. Reconnect with last **applied** cursor; duplicates are legal and client application is idempotent by local sequence. Cursors below the retention floor return explicit `resnapshot_required` plus floor and snapshot endpoint; do not silently skip a gap. Heartbeats have no sequence. Bound per-client queues; overflow disconnects or emits an explicit resync, never blocks ingestion. Coalesce visual updates only after persistence and never coalesce lifecycle/approval/exit/gap records. Large outputs may retain a bounded tail with an explicit truncated byte range, not silently masquerade as complete.

A run that is quiet is not necessarily dead: show last event, source connectivity, and separate liveness evidence. Backpressure policy: bound input frame bytes, output bytes per command, per-source queue, and total storage; prioritize lifecycle and stop acknowledgements in separate bounded control lanes. Pause upstream reading only if its documented flow control allows it; otherwise spool within the configured quota, then record a coverage gap and disconnect/reconcile. Never let a slow UI or a stuck provider call occupy the control executor indefinitely.

## 3. Execution and interruption

### Run state and request API

For each attempt, serialize control decisions through a keyed actor/lock plus a DB compare-and-swap on `(run_id, attempt_id, revision)`. Suggested state machine:

```text
queued -> starting -> running -> completed | failed | interrupted
                      |  \-> stopping -> interrupted | completed | failed | unknown
                      \----> unknown -> reconciled source terminal | operator resolution
queued -> cancelled
```

`stopping` means intent recorded, not process death. Terminal state is immutable for that attempt; later output and command exits may still append. `unknown` means evidence is insufficient, not a fabricated interrupt. Source terminal events can race the stop: record both and use the authoritative terminal outcome; show “completed before stop took effect” if applicable. Keep a distinct thread-level queue hold/resume policy from cancelling one queued run. Never infer that a run is active solely from a UI's last event.

`POST /v1/runs/{run}/interrupt` takes `{request_id, expected_attempt_id, expected_revision, mode: "graceful" | "force", scope: "run"}`. `POST /v1/commands/{node}/interrupt` takes the analogous command scope. Require caller authorization, persist actor, target, accepted/rejected intent and an idempotency receipt in the same transaction. Return `202` with request ID and current state on accepted asynchronous work; repeated request ID with identical canonical payload returns the original receipt, and different payload returns `409`. A stale attempt/revision is `409 superseded`; a terminal target returns its existing terminal outcome, without retargeting the newest run. A command not known or not controllable returns explicit `404` or `unsupported`, never a pretend success. Network acknowledgement is not termination. Provide `GET /v1/requests/{id}` and stream updates until confirmed, failed, or unknown.

### Graceful, force, and background work

1. **Graceful run stop:** commit intent, then dispatch the T3-supported selected-run interrupt with stable command/request ID if the transport supports it. Track dispatch acknowledgement separately from source-reported run terminal. If the transport has no idempotency key, a timeout after dispatch is ambiguous; query source before any retry. Never resolve ambiguity by starting a new run or interrupting a newer one. If T3 responds `no_active_run`, reconcile durable state, including commands that may continue.
2. **Force run stop:** offer only after the backend advertises a supported target-scoped force-stop capability or the harness owns the process containment. Require explicit `force` with captured run/attempt, and record the selected target plus whether queued work is held. Use a bounded graceful interval (initial default 3 s) then force; timers are configuration, not a promise. If the source does not expose force stop externally, show “force stop unavailable; provider may still be running” and a recovery action; do not kill a shared T3 server, shared Codex app-server, arbitrary process tree, or process by remembered PID. Never automatically promote a new queued run while containment cleanup could affect it.
3. **Harness-owned background command:** spawn with direct argv and explicit cwd/environment; record a unique launch UUID and process containment identity before allowing control. On Unix, isolate into a dedicated process group/session at spawn and hold a live OS handle; prefer a delegated per-command cgroup or service scope where available for descendants that create new sessions. Signal the owned group with `SIGINT`, wait a bounded grace period, `SIGTERM`, wait, then `SIGKILL`; reap the leader and check containment emptiness. Process groups alone do not contain daemonized/escaped descendants. On Windows create a Job Object with appropriate limits before child execution, use a supported console-control event when applicable, then terminate the job; verify nested-job behavior in the actual deployment. macOS process-group support has the same escape caveat. Avoid PID reuse: never signal a PID/group reconstructed from durable storage after restart without an OS-verifiable live containment handle and launch identity. Detached/escaped descendants or inaccessible remote processes yield `termination_unconfirmed`, with evidence; they are not represented as killed.
4. **T3/provider-owned command:** keep separate from harness children and continue ingesting its output after the root turn settles. If the provider exposes a documented per-command cancellation capability for the concrete node, invoke it and wait for its exit/settlement evidence. Otherwise offer run-level stop only when appropriate and mark individual command stop unsupported. A T3 synthesized command terminal is a provider/orchestrator projection; display its provenance and do not equate it to independent OS exit evidence. `awaited`, background, and user-started service labels affect whether completion waits for the command; an unawaited background command can outlive its run. Stop a selected command, a whole run, and all thread work are distinct scopes with distinct authorization and UX.

Drain stdout and stderr concurrently throughout shutdown and after exit until EOF or a bounded drain timeout; preserve per-stream byte order and label inter-stream ordering as observed, not causal. Bound retained output and annotate truncation. An approval pending at stop becomes cancelled only when the authoritative owner confirms it; late approval responses must be rejected or reconciled by request generation, never replayed into a different attempt.

## 4. Races, recovery, and operating rules

If the harness store fills or becomes unavailable, preserve a separately accessible path to the authoritative T3 interface for intervention. Never imply the harness recorded or confirmed an action performed there; reconcile its actual state when connectivity and storage recover. Validate this recovery path under disk-full conditions.

| Scenario | Required decision/evidence |
| --- | --- |
| Stop races natural completion | Commit request receipt; source terminal determines outcome. No signal sent to a successor attempt. |
| Duplicate stop / double click / retry | Same request ID and payload return same receipt; unique effect and target generation prevent repeated side effects where supported. |
| Stop arrives before provider start acknowledged | Mark desired stop under lock, suppress an unsent start effect; if start may already have crossed the boundary, query/reconcile before targeting that exact run. Never assume timeout means start failed. |
| Run ends, background command still running | Root terminal and command state remain separate; retain command card and post-terminal output. Do not claim all work stopped. |
| Output after exit or reconnect | Accept by source offset/ID if source supports it; otherwise retain observed order with possible duplication/gap warning. No state resurrection from a late delta. |
| Old exit/interrupt event arrives after restart | Resolve exact attempt/node; record late evidence against old generation, do not mutate the successor. |
| One of two clients stops while another starts | CAS/serialized control locks, target attempt/revision; hold queue until cleanup safety is known. |
| Provider dies / stream closes / timeout | Record source loss and last evidence, reconcile snapshot; if source confirms terminal apply it. Otherwise `unknown` and offer recovery; elapsed silence alone is not proof of death. |
| Crash around side effect | Persist intent/outbox first. On restart inspect claimed-but-unconfirmed effects and source state. Retry only with provider-documented idempotency; otherwise leave ambiguous for reconciliation/operator choice. An outbox cannot make external side effects exactly once. |
| Parent run vs child/delegated work | Report and control each scope. Cascading cancellation is explicit and only through a supported T3 operation; preserve child results and surface partial failures. |
| Watcher overflow, rename, or file changes during read | Emit gap and rescan; use stable file handles and content hash for captured versions, retry or label unstable capture; do not invent all intermediate versions. |

On boot acquire an exclusive writer lease; migrate transactionally, verify DB integrity, restore projections/checkpoints, reconnect sources with exponential backoff and jitter, and reconcile nonterminal runs and pending effects. Source epoch changes invalidate cursors only according to the source contract. If replay is unavailable or truncated, create a durable `stream.gap`, load the authoritative snapshot, and mark missing historical detail. A harness-owned child whose live containment cannot safely be reattached becomes `unknown`; a new supervisor design can instead keep an independently authenticated supervisor alive and recover handles via its protocol. Never treat persisted PIDs as ownership proof.

Shutdown: stop accepting new work; checkpoint ingestion, persist intent/effect states, close subscriptions, and apply an explicit per-command shutdown policy (`leave-running` only with a durable supervisor; otherwise stop owned children or report unconfirmed). Restart and network loss must not implicitly cancel T3-owned work. Use write-ahead backups and exercise restore; configure retention/compaction and verify that every retained snapshot has a valid replay floor.

## 5. Security and observability

Bind locally by default. Require authenticated clients for all routes, including event streams and file reads; authenticate WebSockets before upgrade and validate `Origin`/Host, CSRF and DNS-rebinding protections for browser access. Use per-session short-lived, least-privilege tokens and loopback/unix-socket access; remote exposure requires TLS, explicit opt-in and a real user identity/authorization layer. Never ship T3's provider-scoped bearer token to the browser or put tokens in URLs, event payloads, trace attributes or logs. Separate read, approval, start, graceful-stop, force-stop, and artifact-export permissions. Verify target environment/project/run/node on every request, audit actor and result, and rate-limit costly calls.

Treat prompts, tool output, terminal escape sequences, file names and rendered content as untrusted. Render text with escaping, strip or safely parse terminal controls, set restrictive CSP, isolate previews from app origin, and impose format, dimension, decompression, CPU, memory, time, and size limits on image/model/media parsers. Do not execute project HTML/SVG/scripts or model-referenced remote URLs in the privileged UI. Serve files only beneath explicitly allowed roots using handle-relative, no-follow/beneath resolution or an equivalent race-resistant OS facility; reject traversal, symlink escapes and special files. Canonicalization followed by a separate open is not sufficient against a symlink race. Pin/locally package preview dependencies rather than trust a live CDN for privileged views. Credentials, environment variables, paths and generated artifacts may contain secrets: minimize collection, redact known patterns before external export, give retention/deletion controls, and state that heuristic redaction is incomplete.

Use structured logs/traces keyed by local event sequence, environment/thread/run/attempt/node/request IDs and source epoch, never raw secret-bearing prompt/output by default. Track ingest lag, source checkpoint age, gap count, replay lag, durable write failures, storage occupancy, dropped/truncated bytes, subscriber reconnects, active control requests, interrupt acknowledgement and terminal latency, `unknown` outcomes, abandoned effects and leaked owned scopes. Alerts distinguish source unavailable from confirmed process death. Audit events include actor, authorization decision, target, mode, timestamps, accepted/acknowledged/terminal outcome and evidence provenance. Avoid high-cardinality identifiers as metric labels; keep them in logs/traces. Restrict diagnostics, set retention, and make opt-in raw capture bounded and clearly sensitive.

UI contract: show connection and coverage (`live delta`, `timeline-only`, `gap`, `reconciling`), per-run and per-command state, queued vs background work, stop request/acknowledgement/confirmed result, and an accessible force action only when supported. Feed cards may link observed files and revisions, while an inspector shows metadata, provenance, captured history and compare when available. Pausing presentation must not pause ingestion; resuming replays from the last applied local cursor or visibly resnapshots. Preserve selection across new arrivals and prevent a shifted card receiving the click intended for a “new changes” control. Never advertise actual history, process termination, or causal artifact attribution without the corresponding evidence.

## 6. Implementation slices and acceptance gates

1. **Capability spike:** pin a real T3 build, document version and authentication, enumerate supported stream/replay/cursors, send/interrupt/force/command cancellation and permissions for each provider. Record captures from the real transport with consent and sanitize them. If only MCP timeline read is accessible, ship timeline-only semantics; no invented delta stream. Verify source builds and actual endpoints independently of design docs.
2. **Durable core:** Rust workspace with adapter trait, single DB writer, migrations, projections, cursor-based snapshot/replay API and bounded subscribers. Use a deterministic fake source with explicit source ordering, failures and duplicates. Gate: reconnect and snapshot/replay produce identical projection to uninterrupted delivery, including a handoff exactly at concurrent commit; gaps and retention floors are explicit.
3. **T3 adapter:** implement the chosen supported transport; persist source mapping and receipts, reconcile on reconnect; preserve original provenance and source capability flags. Gate: replay real sanitized captures and run an opt-in live provider test against a disposable project, without asserting unsupported source guarantees.
4. **Interrupt and owned execution:** add request API, CAS/state machine, outbox and supervisor/containment backends. Gate: successful graceful and force cases, target safety, ambiguous side effects and actual process exit evidence on each supported OS. Unsupported per-command/force operations remain disabled.
5. **Visuals and artifacts:** connect the feed/inspector to snapshot + replay; add stable file capture and safe previews with explicit provenance and revision retention. Gate: rendered, interactive end-to-end tests with real filesystem changes, burst, pause/resume, selection and reconnect; include native viewer checks for representative images/models, with unsupported cases visibly identified.
6. **Hardening/release:** security and load/fault tests below; backup/restore, retention and runbook. Feature-flag execution and force stop; keep read-only observation usable when control is disabled. Release only after documented results, platform coverage, open limitations and rollback steps are reviewed.

## 7. Test plan and measurable acceptance

Use disposable directories, mock/fake providers for deterministic faults, and owned processes. No test may kill a shared T3/provider process or alter the user's real worktree. Unit tests alone cannot demonstrate real transport or visual parity. Collect test ID, commit/build, OS, source version, configuration, fixture, expected/actual evidence and logs; clean up test-owned children even on failure.

| Level | Required cases and pass criteria |
| --- | --- |
| Schema/property | Unknown kinds and additive fields survive round trip; invalid IDs/oversized frames rejected; every generated interleaving preserves one terminal root outcome per attempt and never changes another attempt. Proptest state-machine permutations for start/stop/exit/late output/duplicates. |
| Journal/stream | Crash injection before/after each transactional boundary, duplicate deliveries, concurrent snapshot handoff, client disconnect at every cursor, queue overflow and retention compaction. Applied projection equals journal replay; no silent gap; no acknowledged event disappears after restart. |
| Outbox/ambiguity | Drop response after effect is delivered, replay same/different idempotency keys, crash during claim and completion. Exactly one effect only where provider guarantees idempotency; otherwise visible `unknown` with no blind retry. |
| Interrupt integration | Stop while starting, running, naturally completing, already terminal, waiting approval, after root completion with live background output; repeated and simultaneous requests; queued successor and stale attempt; shared-provider and no-capability cases. Assert scope, no successor/shared process harmed, and requested/acknowledged/confirmed are distinct. |
| OS containment | Test child plus grandchild, ignores INT/TERM, high stdout/stderr, detached/daemonized escape, launch failure, timeout, PID reuse simulation, parent crash and platform-specific job/group behavior. Check live process/containment state, wait/reap and output drain. Where containment cannot guarantee descendants, assert `termination_unconfirmed`, not pass-by-label. Run on each claimed OS. |
| Real T3 contract | Against pinned disposable instance and each claimed provider: real timeline/stream reconnect, root/child and background events, actual request IDs, graceful stop, and force/per-command only where exposed. Compare recorded source events and harness projection; list gaps, unsupported capabilities and provider/version-specific behavior. |
| Files and security | Traversal, encoded paths, symlink swap during open, special files, oversized payloads, malicious SVG/HTML, terminal escapes, hostile model assets, wrong-origin/unauthenticated requests, token leakage, quota exhaustion and compromised preview inputs. Assert denied access and no executable content in privileged origin. |
| UI and accessibility | Browser/native rendered tests for keyboard and screen reader labels, status updates, selection stability, burst, paused view with live ingestion, history with and without retained content, reconnect/gap and unavailable force. Capture screenshots/video and inspect actual representative image/3D previews; no structural-only visual acceptance. |
| Load and resilience | In a published fixture profile, run 100 concurrent subscribers, 50 active runs and 10 MiB/s aggregate synthetic output for 10 minutes; choose disk/CPU hardware and retention settings in the report. Control requests must remain responsive: p95 local acceptance <250 ms and p99 <1 s under that profile, excluding external provider latency. Verify bounded memory and queues, durable gap/truncation behavior under deliberate overload, and recovery after a kill/restart. These are initial release targets, not measured current performance. |

Manual acceptance: exercise one real coding run that writes an image and code file, inspect observed vs attributed artifacts, interrupt a long harness-owned command, inspect confirmed process exit, then disconnect/reconnect during output and restore from a backup. Independently exercise a T3-owned background command and record whether the selected provider exposes a supported stop. Verify UI states against the source and OS evidence, and write down any provider/platform where guarantees cannot be met. Don't claim completion on a mocked provider, screenshot alone, or a successful stop HTTP response.
