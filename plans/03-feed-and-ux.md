# 03 — Live multimodal feed and human steering UX

## Purpose and evidence

Design a review and control surface for a Rust streaming coding harness around T3 Code. A person should be able to understand what a run is doing, inspect the actual artifacts it produces, intervene at the right scope, and recover their place when activity is fast or connectivity fails. This is a product and integration plan, not a claim that T3 Code already exposes the proposed events or control operations. Adapter capabilities and delivery guarantees must be discovered and tested before enabling any control.

The evidence is [the Inspector feature inventory](../inspector-feature-inventory/INSPECTOR-FEATURE-INVENTORY.md), the current [Live Gallery page](../assets/index.html), [3D helpers](../assets/kit.js), [thumbnail worker](../assets/worker.js), and Rust watcher, event, listing and server code in [src](../src). Screenshots inspected: [live mixed feed](../inspector-feature-inventory/screenshots/p2-live-feed-updated-badges.webp), [code comparison](../inspector-feature-inventory/screenshots/p2-code-diff-compare.webp), [timeline filtering](../inspector-feature-inventory/screenshots/p2-timeline-range-back-to-latest.webp), [model viewer](../inspector-feature-inventory/screenshots/model-viewer.webp), [video playback](../inspector-feature-inventory/screenshots/video-playback.webp), and [overview](../inspector-feature-inventory/screenshots/overview.webp). These are visual references for information density and spatial organization, not permission to reproduce proprietary Inspector assets or code. The inventory's GUI evidence is from a constrained software-rendered environment; source-inferred and unverified behaviors are labeled below rather than treated as tested.

## Product shape

This is a complete everyday coding harness: projects contain persistent, named threads, and a thread contains an ongoing conversation across multiple turns. The media feed augments that conversation; it does not replace it. A user can create and select a project and thread, send a normal message, follow the response as available, continue the conversation, return to history after a restart, and manage multiple concurrent threads. These are first-release requirements, not later polish.

Keep the thread-level Conversation, Activity, and Artifacts navigation visible and in the same location as the person switches between those views or inspects an artifact. Preserve each view's selection, scroll position, filters, and conversation draft when returning. The default theme uses the user-provided dark palette: background #242424, current line #3D3D3D, selection #403D3D, comment #8C8C8C, foreground #F8F8F2, yellow #FFEE99, pink #F92672, orange #FD971F, green #A6E22E and cyan #66D9EF. Preserve readable contrast and offer an eventual theme preference.

Select the thread separately from its view, with one persistent thread navigation strip and a clear workspace scope. Artifact feedback adds a removable, identified reference to the existing draft and carries over any feedback text without replacing that draft. Return from inspection to its actual origin. Show watched-root coverage and suggest an explicit output folder; a file that disappears before capture cannot be recovered. Keep ordinary stop direct where supported, make escalation scope explicit, and keep background work findable. Surface pending decisions and a basic checkout-scoped changes view early.

The primary thread view presents messages in order, with a persistent composer, streamed assistant text when supported, tool activity and results, attachments, approvals and questions in context. Show provider/model, workspace and run state; retain per-thread drafts and scroll position on navigation. Provide thread list, search, rename and archive where T3 exposes them, plus clear empty, disconnected, failed, queued and interrupted states. Launching a new thread and sending a follow-up must use the actual T3 conversation identity and permission model. Do not create a new thread for every message. Preserve normal Markdown/code rendering, copy actions, keyboard navigation and access to earlier paged history. Any unavailable provider feature must be labeled rather than simulated.

Use a responsive three-region workspace: left project/run navigation and folder filters; central live feed with a compact, accessible activity timeline; right contextual inspector. A persistent run header shows project, branch/worktree, run and connection state. Keep the user's current selection, focus, scroll anchor, and inspector open as new activity arrives. At narrow widths, navigation and inspector become independently opened panels, with the feed and composer still usable. Preserve visible paths and textual labels rather than relying on icons, color, or tooltips.

Two complementary views share filters and stable identities:

- **Activity** is an ordered event stream for reasoning, tool calls and results, user messages, approvals, run lifecycle, and artifact changes. Consecutive text deltas form a single expandable message; tool start, streaming output and result form one operation with explicit status. Errors and pending decisions are easy to find without suppressing surrounding evidence.
- **Gallery** is a newest-first grid or path-oriented list of current artifacts, with image/model/video/audio/code previews, source labels, and new/updated states. A separate event-history list includes removals. Do not confuse current file count with activity-event count. Allow jumping from an artifact to the activity that produced it only when a reliable link exists; otherwise say “Observed in folder” and show time/path, not an invented agent attribution.

Global search and combinable filters cover run, agent/lane where supplied, project/root, path, kind, event type, status and time. Display active filter chips, matching counts and a clear-all action. Search paths and message text separately and state which is selected; never search only loaded DOM and imply all history was searched. Support newest/oldest and clear labels for current-file versus event results. An overview can later summarize projects and Git activity, but remains secondary to run controls and must label stale/partial data.

## Feed model and delivery contract

The UI consumes normalized envelopes from a Rust adapter, not provider-specific raw strings. Each event has schema version, stable event ID, session/run ID, monotonic sequence within its declared stream, source, observed time, optional source time, and typed payload. Where available attach agent/operation/parent IDs, artifact ID and revision ID; fields may be unknown. Preserve raw provider event and unknown types for diagnostics while presenting a safe fallback. Do not imply a global order across independently sequenced streams: merge by observed time with source and a deterministic tie-breaker; expose uncertainty or late arrivals. Separate file modification time from observation and run times.

Represent at least: run/turn start and completion, streamed text and final text, tool call/arguments/result and output chunks, warnings/errors, human instructions, approval requests and decisions, artifact add/update/remove, and connection/indexing state. Stream deltas incrementally without announcing every token to assistive technology. Finalization replaces or closes the same message, not a duplicate. Use bounded output with “show more” or retrieve full logs, never silently truncate evidence; visibly label redaction, retention and truncation.

A snapshot plus a resumable sequence/cursor is the preferred contract. On reconnect, request events after the last acknowledged sequence; deduplicate by event ID, identify gaps and reconcile with a consistent snapshot before declaring live. If the provider lacks replay, display “Reconnected; activity may be missing” with the last observed time, reload current state, and do not claim a complete history. Event ingestion and task execution continue when a viewer disconnects or pauses. Bound buffers, decoding, event retention and expensive previews; when overflow or retention eviction occurs, show the affected interval and recovery path. A reload must retain draft and selected identity where still available, with a clear deleted/expired state otherwise.

**Pause feed** freezes the visible ordered snapshot, its displayed artifact revisions and selection, including removals; it does not pause the agent or file watcher. A pending count and connection state remain visible. Resume applies a single consistent catch-up while preserving the scroll anchor and selection; if revisions were not captured, disclose that the frozen artifact can no longer be reproduced rather than showing current bytes as historical. Distinguish this from **Pause run**, which is available only if the adapter has a real pause operation and reports its acknowledgement. Follow is off by default and affects navigation only: new content may be highlighted or opened only when opted in; it never steals composer focus or changes an in-progress approval. When away from the top, use a non-obscuring “N new changes” button with keyboard activation and no pointer fall-through.

Timeline ranges follow Inspector's tested 5 min, 15 min, hour and 24 hour choices, plus explicit custom start/end. Selecting a bucket applies a named range chip; Back to latest removes that time filter without resetting other filters. Provide an equivalent list of time buckets and events for keyboard and screen readers, including range, timezone and count. Historical mode must not be labeled live, and replay controls must not imply that viewing the past reverses the filesystem.

## Artifact inspection and multimodal fidelity

Every card and inspector shows name, root-relative path, kind, size, observed/modified time, preview state and optional run/operation provenance. Selecting an item is separate from opening it or following updates. Details includes absolute path only where authorized, copy path, open/reveal actions and current availability. Removed artifacts remain identifiable in activity; opening requires a captured revision or shows “no longer available.” Clearly differentiate current bytes, cached thumbnail, captured revision, and generated preview. Captured revision IDs refer to immutable bytes; verify hash/identity when a comparison or steering attachment is made. If snapshot capture is unavailable, say so.

- **Images:** preserve transparency checker, fit, 100%, zoom/pan, keyboard alternatives, dimensions and error placeholder. Render SVG safely; animated formats show play/pause and whether a still frame is displayed. Before/after comparison offers a keyboard-operable slider and side-by-side option; identify both revision timestamps and dimensions. No pixel-perfect comparison claim if transforms differ.
- **3D:** retain lazy, bounded, off-main-thread thumbnail generation where possible and cached previews keyed to content/revision and renderer version. Support inspectable GLB/glTF, OBJ, STL, PLY and FBX as capabilities actually tested, including external resource resolution under allowed roots. Orbit, zoom, pan, reset, fit and keyboard/button equivalents; show loading/error/progress and triangle count when known. Preserve vertex color, material, textures and coordinate conventions, or disclose omissions. A thumbnail is a view, not proof of geometric or material correctness. 3D comparison initially uses synchronized independent views; overlays/difference metrics require a separate validated implementation.
- **Video/audio:** lazy poster/waveform, explicit play/pause, seek, elapsed/duration, volume and mute, keyboard controls; no automatic sound. Offer captions/transcript only when available, labeled by source and with timing; playback failures include codec/backend details and retry/open-file options. Copy frame reports success only after clipboard completion.
- **Code/text and tool output:** bounded, virtualized text with language and line numbers, wrap/horizontal scroll toggle, selectable/copyable content, streamed output, and a unified/side-by-side diff with old/new revision IDs and non-color +/- markers. Detect binary/invalid encodings before text shaping, cap huge lines and isolate parser failures. Do not silently treat an extension as proof of content.
- **Unsupported/corrupt/large:** retain a metadata card and path with specific, actionable status. Per-format and per-platform support matrix distinguishes indexed, thumbnail, full preview and playback; do not advertise a format on extension recognition alone. Enforce byte, pixel, duration, geometry and time budgets; cancel off-screen work, dispose GPU resources, keep the interface usable if a worker, decoder or WebGL context fails. Bundle or explicitly report offline dependency availability; current Live Gallery loads three.js via CDN.

## Human steering and decision workflow

Keep an always-visible, multiline composer associated with the selected run and, when supported, a specific agent/lane. Show destination, scope, current run state and delivery behavior next to Send. A draft is local until explicitly sent; switching runs preserves separate drafts and attachments. Enter inserts a newline; a labeled Send button and an advertised shortcut submit. Do not send on accidental focus or selection changes. User text is clearly distinguished from agent messages and tool output, which are untrusted content.

A steering message can reference selected artifacts or activity via explicit “Attach to instruction.” Show exactly what will be sent: canonical run/project and path, revision/hash or captured bytes if supported, media type, and any excerpt/selection. A path reference is not a snapshot; warn if it changed or disappeared and let the person refresh or deliberately send the stale reference. Do not automatically upload local file contents or include unrelated secret-bearing logs. Capability negotiation determines accepted text, image, audio, video and file inputs, size limits and whether links/paths are meaningful to the recipient. Unsupported inputs remain visible with a reason and alternative; never silently discard an attachment.

Show a message lifecycle: draft → sending → accepted/queued → delivered or rejected/failed, with timestamp, target and message ID where supplied. “Accepted” means transport acknowledgement, not that the agent read or obeyed it. A delivered/consumed status appears only with explicit upstream evidence; if no acknowledgement exists show “Sent; receipt unknown.” Retrying uses an idempotency key if supported; otherwise warn that duplicate delivery is possible and offer copy/retry rather than automatic resend. If a run finishes, changes target or disconnects before delivery, keep the draft and make its destination and any retry explicit. Concurrent viewers see attributed messages and decisions when provided; do not invent authorship.

Separate actions and their scope:

| Control | UX and required semantics |
|---|---|
| Send instruction | Goes to the selected run/lane using an explicitly supported steering interface; show whether it is queued for a safe boundary or can interrupt. No unsupported immediate-effect promise. |
| Pause feed / Resume | Presentation-only as defined above. Never affects execution. |
| Pause run / Resume run | Only when exposed and acknowledged by the backend. Show requesting, paused, resumed, failure and unknown states; disable incompatible actions during transition. |
| Interrupt current operation | When supported, name the exact target and consequences. Show requested vs acknowledged vs completed; an interrupt may leave partial output and does not mean rollback. |
| Stop run | Explicitly targets the named run, explains any known impact on running operations and unsaved output, and requires a deliberate confirmation. Pending/unknown state remains until acknowledged. Do not infer termination from a disconnected stream. |
| Approval / question | A persistent, keyboard-accessible decision card shows requester, action, exact scope, inputs/command or resource, expiry and available choices. Submit one explicit decision with acknowledgement; show stale/already-resolved state if another client acted. Never auto-approve or interpret a timeout as approval. Secret entry uses the supported secure channel and is excluded from feed/logs. |

Agent suggestions, file content, logs and thumbnails are data, not authorization to act. A simple conversation instruction must not accidentally approve a distinct pending action. The harness should relay the provider's actual permission model and avoid promising undo for actions outside its control. Show completed actions and relevant failures in activity, with links back to the matching decision where available.

The control surface must authenticate and authorize run actions, including local browser clients, and validate origin and destination before exposing watched files or accepting steering. Current Live Gallery is a local file viewer, and the inventory reports no authentication or Host/Origin check; its existing HTTP boundary is not a safe authorization model for a coding harness. Keep local paths, logs and previews scoped to authorized projects, and display a clear access error rather than leaking details across runs.

## Interaction and accessibility requirements

Use semantic landmarks, headings, labels, buttons, tablists and dialog behavior; visible focus, logical tab order and focus return after panel/modal closure. Grid and list support arrow navigation, Enter to inspect, Space for selection, Ctrl/Cmd+A within the focused collection, range and additive selection, and a visible selection count/action bar. Shortcuts never hijack editable text, browser/system shortcuts, media controls or assistive technology; publish a searchable shortcut list and offer remapping. Provide ordinary buttons for all gestures, including timeline navigation, model orbit/zoom, comparison slider and multi-select. Target WCAG 2.2 AA contrast, reflow and keyboard criteria; verify with actual assistive technology rather than asserting compliance.

Text scales to 200% and reflows at 400% without losing critical controls; allow panels to resize/collapse, avoid clipping long paths or diff lines, and support wrap or horizontal scrolling with discoverable controls. Respect reduced motion, reduced transparency, high contrast and system color scheme; no meaning is conveyed by red/green alone. Batch live announcements into a polite, rate-limited summary with an opt-out; urgent approval/error announcements are actionable and do not repeatedly interrupt reading. Never move keyboard focus or scroll position on incoming events. Supply meaningful alt text where known; filename is identification, not an invented description. Provide accessible text/status for waveform, visualization, and 3D preview, and captions/transcripts for audio/video when supplied.

## Implementation sequence and acceptance

1. **Contract and shell:** inventory actual T3 event/control capabilities and version them; implement run identity, normalized event stream, snapshot/reconnect, accessible shell, draft persistence and honest unsupported states. Exercise multi-run isolation and disconnected/late/duplicate events. Agree ownership and stable API boundaries with harness and storage implementers.
2. **Live feed and gallery:** connect watched roots and artifact identity; ship search, filters, pagination, list/grid, freeze/catch-up, badges and timeline. Test file settle, atomic replacement, update/removal while paused, bursts above UI buffer limits, scrolling and selection during inserts, root changes and watcher limits. Counts must state whether they describe files, loaded items or events.
3. **Inspect and compare:** add bounded revisions and image/code comparisons, then 3D, video and audio previews under negotiated decoder capabilities. Test corrupt, mislabeled, huge, Unicode, animated, resource-dependent and missing files in isolation. Test actual image/3D appearance, including materials, and playback, not just metadata or a successful loader return.
4. **Steering and decisions:** integrate supported message, interrupt, pause and approval operations with explicit scope, acknowledgements and idempotency behavior. Test two clients, stale decisions, finish-during-send, disconnect/retry, invalid attachments and no-ack providers. Persist neither secrets nor unsolicited attachments.
5. **Polish and validation:** run keyboard-only and screen-reader journeys across feed, timeline, inspector, compare, composer and approvals; check reflow, contrast and reduced motion. Exercise slow/no network, no GPU, missing media codecs, unavailable file picker/clipboard, cache eviction and large project history. Verify clipboard payload and exported files, not just a toast. Capture native/browser screenshots and hands-on playback/interaction evidence, including actual before/after image and model fidelity.

Release gates: no lost/duplicated acknowledged messages under the supported delivery contract; a feed pause has the stated frozen behavior; new events cannot change selection, focus or activate the item under a moving control; malformed media cannot crash the feed; every failure or partial-history state is visible; all primary actions are keyboard operable; and capability claims match a recorded platform/format test matrix. Record throughput, time to first visible event, memory and input latency on representative workloads before setting performance SLOs; never hide dropped data to meet a speed target.

## Open integration decisions

- Which T3 interfaces expose structured events, replay cursors, stable IDs, exact operation targets, delivery acknowledgement, permissions and cancellation? Prototype the adapter against actual supported versions before committing UX promises.
- What durable retention, artifact capture, storage quotas and privacy/redaction policy does the harness provide? The UI must expose the real answer, including eviction and inability to reconstruct old file bytes.
- Which formats, image sizes, media codecs, model dependencies and external resources are supported offline on each target platform? Complete the matrix with real fixtures and fidelity checks.
- How are multiple worktrees, concurrent clients, agent identities and run-to-file provenance bound? Until authoritative, show observational association only.
- Which system picker, clipboard, file-manager and external-app integrations exist on each platform, and what fallback is available? A path-entry fallback and explicit errors are required where a picker is absent.
